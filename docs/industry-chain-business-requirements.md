# CNINFO 全主题产业链采集业务需求文档

## 1. 文档定位

本文是产业链采集项目的业务需求文档，描述业务要什么、数据怎样表达、以后怎样和 CNINFO 的其他数据联动。

本文不指定数据库产品、不指定表的物理实现、不编写爬虫代码，也不要求本轮建设数据库服务。数据库部分只定义后续系统必须具备的业务能力和数据关系。

## 2. 业务目标

从 CNINFO 产业链中心获取全部产业链主题、主题下的全部已知节点以及每个节点对应的企业，输出为业务现有的九字段 Excel，并保留可供后续产业营收、产业链资讯、产业政策、热点趋势等数据联动的结构化中间数据。

最终希望把当前的：

```text
搜索网页/PDF/研报
  ↓
Agent 阅读并建树
  ↓
人工审核
```

扩展为：

```text
CNINFO 产业链节点树
  ↓
逐节点获取企业
  ↓
结构化中间数据
  ↓
九字段 Excel
  ↓
后续联动其他 CNINFO 数据
```

CNINFO 结果是产业链骨架和企业候选集合，不直接等同于完整的上下游供销关系，也不替代所有外部来源和人工审核。

## 3. 采集范围

### 3.1 主题范围

- 从 CNINFO 产业链中心根目录发现全部主题。
- 每个主题以 CNINFO 返回的主题名称和 `chain_id` 作为正式身份。
- 主题目录、主题分类和主题顺序需要保留。
- 不按人工输入的关键词猜测主题，不自行合并名称相近的主题。

### 3.2 节点范围

- 节点范围以该主题页面已经提供的产业链树和“其他”区域节点为准。
- 节点层级只做到网站当前已知的节点层级，不因节点页面里的推荐行业或上下游关联继续无限扩展。
- 产业链树中的每一个可读独立节点都要保留，包括父节点、无企业节点和没有行业编码的节点。
- 同一主题中同名但父路径不同的节点必须分别保留。

### 3.3 节点访问规则

- 每个节点实际进入/请求一次，获取该节点自己的企业集合。
- 父节点和子节点是两个独立采集单元；有编码的父节点和子节点分别查询。
- 企业查询必须按照接口分页总数完成，不允许只取第一页。
- 无 `industry_code` 的节点仍输出节点业务行，但公司字段为空，不发送空编码企业查询。

## 4. 分类和路径规则

### 4.1 分类1允许值

业务分类1的允许值为：

```text
其他、上游、中游、下游
```

行的来源顺序仍以网站顺序为准，不按文字排序重新排列。

### 4.2 页面分区到分类1

| CNINFO 页面分区 | 业务分类1 |
| --- | --- |
| 页面“其他”区域 | `其他` |
| 上游 | `上游` |
| 中游 | `中游` |
| 下游 | `下游` |

当前网站接口中，页面“其他”区域的节点可能以 `tier0` 和 `chain_up_down=未分配节点` 表示。业务上应映射为 `其他`，同时保留接口原始值用于审计。只有确认节点来自页面“其他”区域时才允许该映射，不能把任意未知标签都默认为“其他”。

### 4.3 节点路径进入分类2–4

- `分类1` 填上面的页面分区。
- `分类2` 填路径中的第一个节点。
- `分类3` 填路径中的第二个节点。
- `分类4` 填路径中的第三个及之后节点，并按来源顺序以 ` > ` 连接。
- 分类必须连续，不能跳过中间级别。
- 节点名称、节点层级、父子关系和顺序保持 CNINFO 原义，不标准化、不润色、不用行业知识补全。

### 4.4 业务示例

网站节点树示例：

```text
其他
└── 焊带

上游
└── 太阳能电池零部件
    ├── 太阳能EVA胶膜
    └── 光伏玻璃

中游
└── 太阳能生产设备
    └── 电池片生产设备
```

分类字段应表现为：

```text
分类1 | 分类2 | 分类3 | 分类4
其他  | 焊带  |       |
上游  | 太阳能电池零部件 |       |
上游  | 太阳能电池零部件 | 太阳能EVA胶膜 |
上游  | 太阳能电池零部件 | 光伏玻璃 |
中游  | 太阳能生产设备 | 电池片生产设备 |
```

## 5. 九字段 Excel 需求

### 5.1 固定字段

输出 Excel 只能有以下九个业务列：

```text
主题、信源主体、分类1、分类2、分类3、分类4、公司、信源URL、备注
```

### 5.2 行语义

一行表示：

```text
一个主题
  + 一条从分类1到当前节点的完整路径
  + 该路径终点直接对应的企业集合
```

具体规则：

- 不是一家企业一行；同一节点企业去重后在一个“公司”单元格中用顿号连接。
- 父节点单独成行，不能只输出有企业的叶子节点。
- 无企业节点单独成行，公司为空。
- 同一父节点下的并列子节点分别成行，不能合并成一个分类名称。
- 备注只在该来源组的第一行填写。
- 来源 URL 必须是产生该节点和企业证据的 CNINFO 节点地址，并生成可点击超链接。

### 5.3 字段映射

| Excel 字段 | 业务要求 |
| --- | --- |
| 主题 | CNINFO 正式主题名称 |
| 信源主体 | `CNINFO产业分析系统` |
| 分类1 | `其他`、`上游`、`中游` 或 `下游` |
| 分类2 | 路径第一级节点 |
| 分类3 | 路径第二级节点 |
| 分类4 | 路径第三级及更深节点，使用 ` > ` 连接 |
| 公司 | 当前节点直接返回的去重企业名称集合 |
| 信源URL | 当前节点 CNINFO 页面地址 |
| 备注 | 来源组首行说明，例如“来自CNINFO产业链中心结构化数据” |

### 5.4 公司字段规则

- 公司字段保存接口返回的企业实体名称。
- 若接口返回完整名称，保存完整名称；只能识别简称或品牌时保留原文，不调用外部知识补全。
- 股票代码、企业内部 ID、上市状态、企业标签不拼入公司字段；这些信息由中间数据保存。
- 企业只挂在接口直接返回的当前节点，不从父节点或兄弟节点继承。
- 企业出现于年报产品披露、上市公司检索和非上市企业检索时，应合并去重，但保留企业来源类型。
- 无法确认企业属于哪个节点时，公司留空，不删除节点，不猜测挂载。

## 6. 数据库/中间数据需求

### 6.1 建设目的

Excel 适合交付和人工查看，但不适合作为后续联动 CNINFO 其他数据的唯一数据源。项目需要在“网站采集”和“Excel 输出”之间增加一个可查询、可追溯、可增量更新的结构化持久化层。

该持久化层可以由数据库或等价的结构化存储提供，本需求不限定技术产品。它必须支持：

- 节点和企业的独立保存；
- 节点与企业的多对多关系；
- 同一企业关联多个产业链主题或多个节点；
- 同一节点关联多种企业证据来源；
- 采集运行历史和数据版本；
- 后续其他 CNINFO 数据模块的挂接。

### 6.2 必须保存的逻辑对象

数据库至少要能表达以下逻辑对象，不要求按这些名称建立物理表：

#### 主题对象

保存：

- 来源系统；
- CNINFO `chain_id`；
- 主题正式名称；
- 主题目录分类；
- CNINFO 主题页面或主题来源 URL；
- 首次发现时间、最近采集时间和当前状态。

#### 节点对象

保存：

- 来源系统；
- `chain_id`；
- CNINFO `node_id`/`cnode_id`；
- 节点原始名称；
- 父节点关系；
- 完整来源路径；
- 来源分组；
- 节点层级；
- 上游/中游/下游/其他业务分区；
- 原始 `chain_up_down`；
- `industry_code` 和 `industry_name`；
- 节点页面 URL；
- 节点当前状态。

#### 企业对象

保存：

- 接口返回的企业实体名称；
- CNINFO 企业 ID、股票代码等原始标识（接口提供时）；
- 上市/非上市原始状态；
- 企业原始地址、行业标签等后续查询需要的字段；
- 最近发现时间和最近更新时间。

企业名称不能因为进入数据库而被外部知识改写；原始名称和规范化匹配依据都应可追溯。

#### 节点—企业关系对象

保存：

- 主题和节点标识；
- 企业标识；
- 关系来源接口；
- 是否为年报产品披露、上市检索或非上市检索；
- 接口返回的产品/行业匹配字段；
- 采集时间；
- 产生证据的 CNINFO URL；
- 该关系在当前采集版本中的状态。

该关系不能只保存一个最终公司字符串，必须能回答“这家公司为什么挂在这个节点上”。

#### 来源记录对象

保存：

- 请求接口；
- 请求参数中与业务相关的节点/行业编码和页码；
- 响应状态和业务状态；
- 返回总数、页码和实际行数；
- 原始响应或原始响应的可追溯引用；
- 采集时间；
- 数据版本或运行标识；
- 错误、重试和失败原因。

认证凭据、Cookie、token、sign、密码等敏感信息不得进入该对象。

#### 采集运行对象

保存：

- 运行标识；
- 运行开始和结束时间；
- 主题总数、节点总数、已完成数、失败数；
- 每个主题和节点的状态；
- 重试次数和最后错误；
- 对应 raw、关系数据、Excel 版本和验证结果。

运行对象必须支持断点恢复和重复运行对照，不能只保存最终一次结果。

### 6.3 稳定关联键

后续联动至少需要以下稳定关联关系：

```text
source_system + chain_id
source_system + chain_id + node_id
source_system + chain_id + node_id + industry_code
company_code 或 CNINFO company_id
```

如果接口没有企业代码，必须保留原始企业名称作为临时匹配依据，并标记匹配置信度或标识缺失状态，不能伪造企业代码。

### 6.4 后续数据联动要求

持久化层后续应允许把 CNINFO 其他页面或接口数据挂到以下对象上：

- 主题：产业链整体的产业营收、政策、资讯、热点趋势；
- 节点：节点行业营收、上下游关联、节点相关新闻、节点政策；
- 企业：企业营收、企业公告、企业资讯、企业融资或上市信息；
- 时间：数据发生时间、报告期、发布日期和采集时间必须区分。

后续联动数据不能覆盖产业链主数据，而应通过来源、对象标识和时间形成独立数据记录。不同接口的统计口径必须分开保存。

### 6.5 Excel 与数据库的关系

- 数据库/中间数据是可追溯的结构化事实层。
- Excel 是面向业务人员的九字段输出视图。
- 每个节点企业分页完成并通过校验后，才允许增加该节点的业务行。
- Excel 增加业务行不应导致数据库关系重复；重复运行应执行幂等更新。
- Excel 可以按已完成节点实时更新；未完成节点不能用空企业结果伪装成已完成。
- 数据库中的企业关系、来源接口和运行状态不新增到 Excel 业务列中；需要时通过 sidecar 或后续查询查看。

## 7. 增量和实时更新需求

### 7.1 节点级原子更新

业务上把一个节点视为一个最小提交单元：

1. 节点页面/接口请求成功；
2. 该节点的企业接口完成所有分页；
3. `total`、页数、实际行数和关键字段通过校验；
4. 数据库/中间数据写入该节点及节点—企业关系；
5. Excel 增加或更新该节点的一行；
6. 该节点状态变为已完成。

如果第 1–3 步失败：

- 不写入完成状态；
- 不用空公司覆盖旧结果；
- 保留错误、页码和响应证据；
- 允许后续只重试该节点。

### 7.2 幂等要求

- 同一来源、主题、节点和完整路径重复采集不能产生重复业务行。
- 同一企业在多个接口返回时不能造成公司字段重复。
- 同一节点重试成功后应更新原关系或新版本，不追加一份无法区分的重复关系。
- 数据更新要能区分“首次发现”“本次采集”“历史版本”和“当前有效”。

## 8. 数据质量要求

- 节点树必须能从来源关系恢复，不能先套用标准产业链再填 CNINFO 节点。
- 节点名称、路径和顺序必须保持来源原义。
- 企业必须来自当前节点直接返回的接口证据。
- 企业接口必须按 `total` 分页，不能只取第一页。
- 页面“总计”与 API `total` 应对抽样节点进行对照；不一致时保留差异。
- 年报披露、上市检索、非上市检索的数量和来源类型分开统计。
- Excel 列数固定为九列，URL 可点击，业务行能够被数据库关系追溯。
- 采集失败、接口变更、无行业编码和企业为空都必须有明确状态，不能静默丢弃。

## 9. 非功能需求

### 可恢复性

进程中断、页面刷新、单节点超时或登录态短暂失效后，已完成节点不能丢失，未完成节点可以继续处理。

### 可追溯性

任意 Excel 行都应能追溯到主题、节点、完整来源路径、节点 URL、企业关系来源和采集运行。

### 安全性

浏览器登录态只用于访问 CNINFO；密码、Cookie、token、sign 和请求认证信息不得写入代码仓库、数据库、日志或 Excel。

### 可扩展性

后续新增 CNINFO 产业营收、产业链情报、产业政策、热点趋势等数据时，不应破坏主题、节点、企业和节点—企业关系，也不应强迫 Excel 增加业务列。

## 10. 明确不在本需求内

- 不要求使用 LLM 自动建立 CNINFO 已提供的节点树。
- 不要求通过截图或 OCR 获取结构化字段。
- 不要求补全 CNINFO 未返回的企业或供销关系。
- 不要求本轮选择 MySQL、PostgreSQL、SQLite、MongoDB 或其他具体数据库产品。
- 不要求本轮建设数据库管理后台或 Web UI。
- 不要求把一家企业拆成 Excel 中的一行。
- 不要求无边界地递归网站推荐的上下游节点。

## 11. 验收标准

### 主题与节点

- 全部主题能够被发现并具有唯一 `chain_id`。
- 每个主题的上游、中游、下游和其他节点均有来源路径。
- 父节点、并列节点、无企业节点和无编码节点没有被遗漏。

### 企业

- 每个节点实际获取一次自身企业数据。
- 有行业编码的节点完成企业接口分页。
- 无行业编码节点不发送空编码请求，且仍保留节点行。
- 企业名称去重后按来源顺序写入当前节点公司字段。

### Excel

- Excel 只有九个业务列。
- 分类1只能使用 `其他/上游/中游/下游`，节点从分类2开始。
- 每个节点对应一条完整路径业务行，企业不是一家一行。
- URL 可点击且指向产生该行证据的 CNINFO 节点页面。
- 节点完成后可以实时增加或更新业务行，重复运行不重复增加。

### 数据库联动

- 主题、节点、企业、节点—企业关系、来源记录和采集运行均可保存或追溯。
- 一个企业可以关联多个节点，一个节点可以有多种企业证据来源。
- 后续其他 CNINFO 数据能够通过主题、节点、企业和时间关联，不需要修改九字段 Excel。
- 数据库/中间数据和 Excel 的状态、数量、来源能够对照。
